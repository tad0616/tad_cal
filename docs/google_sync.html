tad_cal 與 Google 行事曆雙向同步設定教學

依照以下步驟設定 Google OAuth、連結行事曆分類，並安排定期同步。

本功能以「一個 tad_cal 分類對應一個 Google 行事曆」。本站事件新增、修改或刪除時會立即嘗試同步到 Google；Google 端變更則由伺服器排程定期同步回本站。

快速目錄

  1. 開始前請確認
  2. 建立 Google OAuth 用戶端
  3. 在 XOOPS 輸入 OAuth 資訊
  4. 設定分類並授權
  5. 選擇首次同步方式
  6. 設定定期同步排程
  7. 確認同步運作
  8. 常見問題與注意事項

開始前請確認

  • XOOPS 網站有固定網址，並建議使用 HTTPS。
  • 執行網站及排程的 PHP 均啟用 cURL 與 OpenSSL。若網站 PHP 與命令列 PHP 使用不同設定，請分別確認。
  • XOOPS 資料庫可正常連線，且已備份資料庫。
  • 要連結的 Google 帳號對目標行事曆具有編輯權限。若使用共用行事曆，請先在 Google 行事曆分享設定中授予該帳號變更活動的權限。

一、建立 Google OAuth 用戶端

  1. 登入 Google Cloud Console。
  2. 建立或選取一個專供此網站使用的 Google Cloud 專案。
  3. 在「API 和服務」的 API 程式庫中搜尋並啟用「Google Calendar API」。
  4. 開始設定 OAuth 同意畫面（部分帳戶會顯示 Google Auth Platform 設定）：
    • 填寫應用程式名稱及支援電子郵件。
    • 依使用對象設定應用程式對象／使用者類型，並填妥要求的聯絡資訊。
    • 若應用程式仍處於測試狀態，將要進行授權的 Google 帳號加入測試使用者。
    • 不需要自行新增行事曆 scope；授權時 tad_cal 會要求 Google 行事曆事件的讀取與編輯權限。
  5. 在「用戶端」或「憑證」中建立 OAuth 用戶端 ID，應用程式類型選「網頁應用程式」。
  6. 在「已授權的重新導向 URI」新增以下網址。從後台開啟本教學時，網址會自動帶入目前 XOOPS 網站的網址，請直接複製： 
    https://你的網域/modules/tad_cal/google_sync.php
    若直接開啟此文件，請將示意網址換成實際 XOOPS 網站的完整網址。 網址、網域、通訊協定及路徑都必須與 XOOPS 設定一致；不要加上 op 或 cate_sn 參數。
  7. 建立後複製「用戶端 ID」及「用戶端密碼」。請勿公開密碼或提交到版本控制。
正式提供給多位使用者使用時，請依 Google Cloud 顯示的發布狀態及驗證要求完成必要設定。測試中的應用程式只能由已加入的測試使用者授權；Google 也可能因使用者或應用程式政策撤銷 refresh token。

二、在 XOOPS 輸入 OAuth 資訊

  1. 登入 XOOPS 管理後台，進入「模組」管理。
  2. 找到 tad_cal；若剛安裝或更新模組，先執行模組更新，讓雙向同步所需資料表建立完成。
  3. 開啟 tad_cal 的「偏好設定」。
  4. 將 Google Cloud 提供的「用戶端 ID」及「用戶端密碼」分別貼入「Google OAuth 用戶端 ID」及「Google OAuth 用戶端密鑰」。
  5. 儲存設定。

三、設定分類並授權 Google 行事曆

  1. 在 XOOPS 管理後台開啟 tad_cal 的「行事曆管理」，新增分類或編輯現有分類。
  2. 在「Google 行事曆 ID」輸入目標行事曆 ID：
    • 主行事曆可填 primary。
    • 其他行事曆可在 Google 行事曆網頁版的「設定及共用」>「整合行事曆」中找到「行事曆 ID」。
  3. 選擇「首次同步方式」（詳見下一節），儲存分類。
  4. 在該分類設定頁按「連結 Google」。
  5. 選擇有權限存取該行事曆的 Google 帳號，檢查授權帳號後同意 tad_cal 存取。授權成功後會返回該分類設定頁，狀態應顯示「已連結」。
  6. 在分類設定頁按「立即同步」完成首次同步。若頁面沒有返回或顯示錯誤，請先按錯誤訊息檢查 OAuth URI、用戶端資訊、Google 帳號權限及 PHP 擴充設定。

四、選擇首次同步方式

首次同步方式會影響分類中既有的本站事件。選擇前請先備份，並與分類使用者確認。

  • 匯入 Google 事件；既有本站事件不推送：Google 事件會匯入本站，既有本站事件不會在首次同步上傳，之後編輯該事件才會開始同步。若兩邊原本已有相同事件，可能出現重複資料。
  • 以 Google 為準：首次同步會刪除該分類既有的本站事件，再匯入 Google 事件。此操作不可復原，執行前頁面會要求勾選確認；建議先備份。
  • 合併雙方事件並上傳本站既有事件：本站既有事件會上傳至 Google，再匯入 Google 事件。若兩端原有相同事件，可能產生重複資料。
重要：「以 Google 為準」會刪除該分類既有的本站事件。若不確定該選哪一項，先備份並選擇不會刪除既有事件的策略。

五、設定定期同步排程

本站的事件變更會即時推送；Google 端的變更需要執行 cron_sync.php 才會拉回。請在伺服器設定每五分鐘執行一次。此程式只允許命令列執行，請勿以瀏覽器開啟。

Linux / Unix（crontab）

*/5 * * * * /usr/bin/php /完整路徑/xoops/modules/tad_cal/cron_sync.php >> /完整路徑/tad_cal_google_sync.log 2>&1

請將 /usr/bin/php 及 XOOPS 路徑替換成伺服器實際位置。可用 crontab -e 編輯排程；若伺服器的 PHP 不在 /usr/bin/php，請使用主機商提供的 PHP CLI 路徑。

Windows 工作排程器

  1. 建立基本工作，觸發程序設為每天，並設定每 5 分鐘重複、持續時間選「無限期」。
  2. 動作選「啟動程式」：
    • 程式或指令碼：PHP CLI 的完整路徑，例如 C:\php\php.exe
    • 新增引數：C:\完整路徑\xoops\modules\tad_cal\cron_sync.php
    • 開始位置：XOOPS 網站根目錄（如有需要）
  3. 儲存後檢查工作歷程及上一個執行結果。請確認排程使用的 PHP CLI 已啟用 cURL、OpenSSL，且可以連接 Google API。

先手動測試排程命令

先在命令列執行一次，確認路徑與 PHP 環境正確：

php /完整路徑/xoops/modules/tad_cal/cron_sync.php

同步完成時會逐一顯示已同步的分類；若有錯誤，錯誤分類會輸出原因且程式以非零狀態結束。排程可將輸出導向記錄檔，方便管理員排查。

六、確認同步運作

  1. 在已連結的 tad_cal 分類新增一筆測試事件，確認 Google 行事曆出現該事件。
  2. 在 Google 行事曆修改或新增另一筆測試事件，等待下一次排程執行，再確認本站有同步更新。
  3. 測試刪除前請注意：配對事件在任一端刪除，刪除會傳遞到另一端。
  4. 同步衝突以較新版本為準。排程間隔期間的 Google 端更新，會在下一次排程處理。

常見問題與注意事項

  • redirect_uri_mismatch：確認 Google Cloud 的已授權重新導向 URI 與 XOOPS 網址完全一致，包含 http/https、網域及路徑。
  • Google 帳號看不到目標行事曆：確認該帳號已有該行事曆的編輯權限，並重新授權。
  • 沒有取得 refresh token：在 Google 帳戶的第三方應用程式／安全性設定中移除 tad_cal 授權，再回到分類頁重新連結。
  • 排程執行失敗：確認命令列 PHP 的 cURL、OpenSSL、XOOPS 路徑及資料庫設定；網頁 PHP 正常不代表 PHP CLI 使用相同設定。
  • 更換 XOOPS 資料庫密碼後：refresh token 使用資料庫密碼衍生的金鑰加密，請重新連結 Google 行事曆。
  • 解除連結：會移除本站的授權及事件對應資料，但不會刪除任一端的事件；解除後雙向同步即停止。
  • 重複事件：支援 tad_cal 可處理的重複規則。Google 重複事件的單次例外（例如只修改或取消其中一天）目前不支援，排程會回報同步錯誤。
  • 時區：重複事件時間會依 PHP 伺服器時區正規化；請確認伺服器時區設定正確。
