Google Calendar two-way synchronization
========================================

Setup
-----

0. Update the tad_cal module from XOOPS module administration to create the synchronization tables.
1. Enable the Google Calendar API in a Google Cloud project and create an OAuth web application.
2. Set the authorized redirect URI to the exact XOOPS URL for `modules/tad_cal/google_sync.php` (HTTPS is recommended).
3. Enter the OAuth client ID and secret in the tad_cal module preferences.
4. In a calendar category, enter its Google Calendar ID (`primary` for the primary calendar), save, and connect Google.
5. Select the initial synchronization policy carefully:
   - Keep local events: import Google events, keep existing site events local-only until edited.
   - Replace local events: delete existing site events in this category and import Google events. This is irreversible.
   - Merge: upload existing site events and import Google events. This may create duplicates.
   The first sync must be started from the category settings; the replace option requires an explicit confirmation.
6. Configure a system scheduler to run `php /path/to/xoops/modules/tad_cal/cron_sync.php` every five minutes.

Local changes are pushed immediately. The scheduled job imports Google-side changes and propagates deletions. The server needs PHP cURL and OpenSSL.

Google refresh tokens are encrypted using the XOOPS database password. Reconnect Google if that password changes. Disconnecting removes the token and event links but preserves events on both sides.

Recurring series are synchronized when they use an RRULE supported by tad_cal. Times are normalized to the PHP server time zone. Per-occurrence Google exceptions (such as changing or cancelling one date in a series) are not supported and are reported as sync errors instead of being silently discarded.
